## 二、「四步演示」指哪四步

**按界面上真实存在的动作定义**，不按 API 走查定义。两者在第 2、3 步上分岔，
这一点必须写在前面，否则试用者会被记成「找不到入口」而不是「产品没这个入口」。

| # | 界面上的动作 | 期望 | 用哪个账号 |
| --- | --- | --- | --- |
| 1 | 登录，并说清自己现在在哪个班 | 能自己找到并在页面上看到班级 | `student_a1` |
| 2 | 上传一份自己的 `.md` / `.txt`，在材料列表里找到它 | 新材料出现在列表 | `teacher_a` |
| 3 | 用刚上传材料里的一个词去检索（`知识检索` 页） | 结果里出现那份材料 | `student_a1` |
| 4 | 换另一个账号检索同一个词 | **搜不到**（跨班隔离）；能否自己发现并说出原因，是观察重点 | `student_b1` |

> 这套**界面四步**天生跨角色：第 2 步只有教师能做（学生上传 403 是设计），第 4 步只有 B 班账号能做。
> 第一批因此只能是「四步都有人走过」，不是「一个人走完」。
> **第二批改走课件原义的四步**（登录 → 提交 202 → 轮询 → 换班 404），这四步不跨角色：
> 一个人持 A 班 + B 班两个账号即可独自走完，三人各自走完了全程，见第五节。

### 为什么不用 API 走查那四步

第 10 课验收用的自动走查四步是：登录 → `POST /api/submissions`（202 + `task_id`）
→ 轮询 `GET /api/tasks/{id}`（`pending → running → succeeded`）→ 跨班 404。
那套是**给开发侧自动化用的**（`scripts/h5_walkthrough.py` 已覆盖，实测全绿）。

它不能直接拿去考**桌面端**的真实用户，因为桌面页面没有提交入口：页面路由只有
`/materials`、`/knowledge`、`/tutor`、`/mcp` 与教师面板，作业提交只暴露了 API。
**但 `/m` 轻量端四个动作全有**——登录、加载本班材料、提交并轮询、跨班取详情都在页面上，
课件第 10 课指定的入口正是「手机浏览器打开轻量端」，第二批就是在这个页面上走的。

桌面端缺提交入口这件事本身仍是一条改进项（用户要在桌面上交作业得绕到 `/m`），
与"轻量端能不能用"是两件事，不合并记。

所以：**API 四步用于自动化验收，界面四步用于真实用户试用**，两套都在，
各自证明不同的东西。界面上缺少提交入口这一点，本身记作一条改进项
（见本文档记录表的「去向」列与 `reports/user-trial-record.md` 的观察重点）。

界面上对应的入口：`/materials`（材料）、`/knowledge`（检索）、`/qa`（答疑）、
`/tutor`（解题助手）、`/dashboard`（教师面板）。给使用者时**只给地址与账号，不给操作说明**。

### 逐条证据（可自行复核）

```sql
-- 三个任务的状态与三段时刻
SELECT task_id, class_id, status, attempts, max_attempts, error,
       created_at, started_at, finished_at
FROM grade_tasks
WHERE task_id IN ('task_278935aa4b875342','task_3980bb16760618cf','task_f958203c76e59683');

-- 提交与跨班：六条流水
SELECT ts, actor, class_id, method, path, status, code
FROM audit_events
WHERE ts >= '2026-11-14T10:52' AND ts < '2026-11-14T10:58' ORDER BY ts;

-- 登录：六个时刻各一行
SELECT user_id, created_at FROM auth_sessions
WHERE created_at LIKE '2026-11-14T10:5%' ORDER BY created_at;
```

实测结果：三条任务均 `status=succeeded`、`attempts=1`、`max_attempts=3`、`error` 为空，
`created/started/finished` 分别落在 10:52:48–52、10:54:38–42、10:56:32–35（UTC）；
六条流水与上表逐秒对应；`auth_sessions` 六个时刻（10:52:29 / 10:53:19 / 10:54:21 /
10:55:11 / 10:56:16 / 10:57:06）各自对应一次登录，含两次换班登录。

材料归属：`#7` 属 `class 1`（A 班《第三章 二元一次方程组讲义》）、`#8` 属 `class 2`
（B 班《英语写作课讲义》）。`GET /api/materials/{id}` 按 `id + class_id + status='active'`
联合定位，跨班与不存在走同一条分支——所以 404 不是权限判出来的，是查询条件里就带了班级。

### 提交客户端（写明，不当作界面操作证据）

三轮提交均由 `scripts/h5_walkthrough.py` 在**同一台试用机**上执行，因此
`grade_submissions.assignment_ref` 记为「轻量端走查 18:52:48」这类格式（脚本按
`time.strftime('%H:%M:%S')` 生成），三条作答都是页面默认句、`content_hash` 相同。
这不影响四步本身——登录、202、状态推进、404 都由服务端记录（见上表与 SQL）——
但"提交动作是人点的还是脚本跑的"从库里分不出来，所以把客户端写在这里。
若后续批次希望连这一点也可区分，让每人手打一句不同的话提交即可（`content_hash` 会各不相同）。

### 局限

- 三人共用同一台试用机；`audit_events` 无 IP / UA 字段，流水能证明
  「三个账号、三个时段、三次独立登录」，证明不了「三个自然人」。这条照旧不改写。
- 入口是局域网地址（手机热点网段），不是公网域名；判据 4 的地址要求仍按 4.7 之前那份记录判，
  不拿这一批去顶。
