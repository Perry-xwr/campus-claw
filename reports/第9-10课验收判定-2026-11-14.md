原文写的是 `https://<部署域名>/claw/`，两个词都硬：`https` 与「部署域名」。当前只有 `http://127.0.0.1:8110/claw/` 与 `http://172.20.10.2:8110/claw/`。

## 六、本次复核遇到的问题：本机跑不了门禁

复核时在本机跑 `scripts/check_all.py`，**4 项红**（async / apitest / observe / compose），原因不是代码回归：

```
ImportError: DLL load failed while importing unicodedata: 应用程序控制策略已阻止此文件。
```

排查结论：

| 检查 | 结果 |
| --- | --- |
| `.venv` 的 Python 3.11 导入 `unicodedata` | **失败**（上述错误） |
| venv 的基础解释器（uv 的 `cpython-3.11-windows-x86_64-none`）直接导入 | **同样失败** |
| 另一个 Python 3.13 导入 | **成功**（`unidata_version 15.1.0`） |
| 应用控制策略状态（`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy`） | `VerifiedAndReputablePolicyState = 1`，即 **Smart App Control 处于强制模式**，拦截了 uv 那份未签名的 `unicodedata.pyd` |

所以本次复核的结论**不基于本机复跑**，而是基于：① 仓库内已归档的证据文件；② GitHub CI（跑在 Linux runner 上，不受本机策略影响，最近一次 `success`）。这一条必须写明——本机现在是红的，把它写成绿就是造假。

要恢复本机复跑，两条路：一是换用 python.org 的签名版 CPython 3.11 重建 venv（SAC 认签名）；二是在容器里跑门禁（需先启动 Docker Desktop，当前 daemon 未运行）。**不建议关 Smart App Control**——关了之后不经系统重置无法再开。
