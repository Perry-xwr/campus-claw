# 真实用户试用记录（第 10 课判据 6）

> 这一项**不能由开发者自测替代**。自测只能证明「按设计的路径能走通」，
> 证明不了「没人教也能用」——后者才是这条判据问的事。
>
> 本文件是空模板，等有真实用户后按格式填。没填之前，报告里这一条保持「未执行」。

## 为什么这条不能凑

课件要的是「真实用户能不能用起来」，三个自测替代不了的点：

1. **路径依赖**：你知道入口在哪，新用户不知道。第一次找「知识检索」和「答疑广场」的区别，是最容易卡住的地方。
2. **术语假设**：界面上的「引导式回答」「班级 FAQ」「采纳」这些词，你看着清楚，别人未必。
3. **失败恢复**：用户点错、传错文件、搜索无结果之后怎么办，只有看别人操作才发现。

## 试用流程（每位约 15 分钟）

1. 只给一条信息：服务地址与账号。**不给任何操作说明**。
2. 让用户自己完成下面 5 个任务，全程不提示、不打断。
3. 记录每步是否完成、卡在哪、说了什么原话。
4. 结束后问 3 个问题（见下）。

### 5 个任务

| # | 任务 | 完成标准 |
| --- | --- | --- |
| 1 | 登录并说清楚当前在哪个班 | 能说出班级名 |
| 2 | 上传一份自己的 `.md` 或 `.txt` 材料并找到它 | 材料出现在列表里 |
| 3 | 用关键词搜到自己刚传的内容 | 结果里出现该材料 |
| 4 | 在答疑广场提一个问题 | 问题出现在列表首位 |
| 5 | 找到本班 FAQ 并读一条 | 能复述 FAQ 讲的是什么 |

### 结束后的 3 个问题

1. 哪一步最费劲？为什么？
2. 有没有哪个词/按钮你不确定是干什么的？
3. 如果明天还要用，你最想先改哪一处？

## 判定口径

| 情况 | 结论 |
| --- | --- |
| 3 位用户 5 个任务全部 `✅` | 通过 |
| 有 `⚠️` 但均有明确改进项并已修 | 通过（附改进前后对比） |
| 有 `❌` | 不通过，记为该轮缺陷，修完重测 |
| 没有真实用户 | **未执行**，不填、不估、不用自测冒充 |

## 已知的观察点（试用时重点看这几处）

这些是自测时已经意识到的模糊点，看真实用户会不会也卡：

- 「知识检索」与「答疑广场」两个入口的区别，首次使用容易混。
- 上传材料时对文件格式的限制（仅 `.txt` / `.md`）是否在界面上提前说清。
- 搜索无结果时，页面有没有告诉用户「换个词试试」而不是只显示空列表。
- 教师视角与学生视角的导航差异，切角色后会不会找不到原来的功能。
