## ADDED Requirements

### Requirement: R91 三段式安全自查记录

七项安全检测 MUST 逐条落到具体身份、具体数据、具体命令或操作，判定只有红或绿两种。

#### Scenario: 每条记录含五要素

- **WHEN** 产出 SEC-01～SEC-07 任一条记录
- **THEN** 记录包含前置条件、操作、可观测结果（期望）、当前实际、当前判定
- **AND** 当前实际写可再次跑出的具体值，不出现「没问题」「应该是好的」这类判断

#### Scenario: 清单齐备且身份数据可用

- **WHEN** 归档 `reports/security-precheck.md`
- **THEN** 文件列出不少于 5 个受保护接口（方法与路径）与写入类接口清单
- **AND** 记录预置账号班级 A / 班级 B / 教师 A / 学生 A1 / 学生 B1 均可登录，且自查在按 README 从零启动的可复现环境中执行

#### Scenario: 只记录现象不提前修复

- **WHEN** 某条检测判定为红
- **THEN** 本课不修改造成该判定的业务代码，仅如实记录并留待后续课次
- **AND** 至少保留 1 条判定为红的条目；密钥明文真实命中是唯一例外，必须立刻轮换并从历史清除

### Requirement: R92 权限类四件事与跨班专项记录

SEC-01～SEC-04 每条 MUST 写清用什么手段查、查了什么、判据、结果；跨班一条单独成文件。

#### Scenario: 未登录访问受保护接口

- **WHEN** 不带任何令牌逐个调用受保护接口清单
- **THEN** 每个接口返回 401，记录逐个接口的实际返回码

#### Scenario: 跨班访问与跨班检索

- **WHEN** 学生 A1 访问班级 B 讲义，并用班级 B 身份检索班级 A 知识库独有内容
- **THEN** 跨班访问返回 404、跨班检索返回空结果（0 条）
- **AND** 本班检索须有结果，以证明检索能力本身可用而非检索整体失效

#### Scenario: 学生改配置与绕过技能路由

- **WHEN** 学生身份调用提示词、技能、助手配置类写入接口，或不走技能路由直调写入接口
- **THEN** 返回 403 且数据库无新增或被改动的记录

#### Scenario: 跨班记录单独归档且可复测

- **WHEN** 归档 `reports/risk-authz.md`
- **THEN** 文件写全「用什么手段查 / 查了什么 / 判据 / 结果」四件事
- **AND** 附一段能在演示机器原样复制执行的复测命令，并注明期望输出

### Requirement: R93 资产类基线归档与一键入口

密钥扫描与依赖审计 MUST 归档命令与输出原文，且能一键复跑。

#### Scenario: 密钥明文扫描三处

- **WHEN** 执行 `make check-security`
- **THEN** 扫描范围包含全量提交历史、前端产物、运行日志，输出命中数
- **AND** 真实密钥明文 0 命中；公开演示/测试常量须逐条登记而非静默过滤

#### Scenario: 依赖审计基线

- **WHEN** 执行依赖审计部分
- **THEN** 归档声明依赖与本机已安装版本清单，给出高危数量或书面登记处置方式
- **AND** 未安装 `pip-audit` 或离线时标注为降级，不谎称高危清零

#### Scenario: 一键入口在 README 中注明

- **WHEN** 查阅 README
- **THEN** 能找到 `make check-security` 与 Windows 等价入口 `pwsh -File scripts/check-all.ps1`
- **AND** 一键命令可覆盖 SEC-05 与 SEC-06 的扫描部分

### Requirement: R94 审计日志字段缺口登记

审计记录 MUST 能按技能标识回查；本课 MUST 把字段缺口单独记一行，并写明准备加在哪一层，供后续课次的监控指标使用。

#### Scenario: 回查一次技能调用

- **WHEN** 触发一次技能调用后回查审计记录
- **THEN** 记录当前日志实际具备的字段，并对照操作人、技能标识、结果状态、耗时、用量逐项核对
- **AND** 缺哪些字段单独记一行，写明准备加在哪一层，作为后续课次监控指标的数据源

### Requirement: R95 固定文件名归档与交叉评审

证据 MUST 归档到仓库根目录 `reports/` 下的固定文件名，且 MUST 有一次由组内另一人独立复现至少 2 条的交叉评审记录。

#### Scenario: 六份记录位置固定

- **WHEN** 第 8 课自查交付
- **THEN** 仓库根目录 `reports/` 下存在 `security-precheck.md`、`risk-authz.md`、`risk-concurrency.md`、`risk-transaction.md`、`security-baseline.md`、`review-01.md`
- **AND** 路径可被最终项目报告直接打开复核

#### Scenario: 并发与事务两条专项记录

- **WHEN** 归档 `reports/risk-concurrency.md` 与 `reports/risk-transaction.md`
- **THEN** 分别记录判据三（重复提交 / 重复投递只出一份结果）与事务一条（提交记录与任务记录同事务，停消费者提交 → 恢复后恰好投递一次、无孤儿任务）
- **AND** 两条都按「用什么手段查 / 查了什么 / 判据 / 结果」四件事写全

#### Scenario: 交叉评审独立复现

- **WHEN** 归档 `reports/review-01.md`
- **THEN** 记录由组内另一人照清单独立复现至少 2 条，写清用什么手段查、查了什么、判据、结果
- **AND** 判定与原记录一致才算通过，复现命令与输出附在文件内

### Requirement: R96 交给后续课次的素材

本课 MUST 为后续课次留下可复用素材与至少一条红条目；异步提交接口的演示链路 MUST 能原样复现并归档命令与输出。

#### Scenario: 先红后绿与素材备齐

- **WHEN** 本课交付完成
- **THEN** 至少保留 1 条红条目，并备齐受保护接口清单、写入类接口清单、知识库测试问题集草稿（有答案 / 无答案 / 跨班三类）
- **AND** `reports/sec08-materials/` 存放 1 份含指令覆盖内容的讲义与 3 条诱导提问，本课只准备不试

#### Scenario: 演示链路可原样复现

- **WHEN** 最终验收当堂演示
- **THEN** 链路能走通「登录取令牌 → 提交作业返回 202 与 task_id → 轮询状态看 pending → running → succeeded」
- **AND** 复现命令与输出归档在 `reports/`
