# CampusClaw 当前实现审查报告

审查日期：2026-11-04  
审查范围：当前 Python/Flask 项目代码、页面模板、SQLite 数据访问、运行说明，以及五模块业务规约。  
结论性质：代码静态审查 + 隔离临时环境自检；不是完整业务验收。业务数据库、上传目录和运行服务未被修改；本次没有运行正式 37 个业务验收场景。

## 1. 整体概览

CampusClaw 已是一个可运行的课程辅助系统，除答疑广场外，还包含班级教学材料管理、知识检索、会话式解题助手和教师配置能力。主应用使用 Python 3.11、Flask、SQLite、Jinja 模板；`uv` 管理本地依赖，Docker Compose 可启动应用、索引 worker、Qdrant 和 MCP 服务。应用入口为 `app.py`，应用工厂在 `campusclaw/__init__.py`。

本审查读取的业务基线是 `docs/requirements/functional-spec.md`、`roles-and-workflows.md`、`acceptance-scenarios.md` 和 `docs/implementation-baseline.md`。其中 14 条需求与 37 个 Scenario 均保留，Scenario 文档状态全为 `NOT_RUN`。当前唯一测试证据是此前使用独立临时目录执行的 `scripts/selfcheck.py`：健康检查、四个种子账号登录及每个账号看到一份本班材料均通过。它不测试答疑业务，也不能作为任一答疑 Scenario 的通过证据。

## 2. 各模块实现情况

### 2.1 登录、角色权限与班级隔离

- **已实现功能：** 页面使用 Cookie 会话；API 支持 Bearer 身份；会话记录保存用户关联和有效期。答疑 API 通过 `qa_login` 限制为已登录班级成员，通过 `qa_teacher` 限制教师操作并对 Cookie 写请求要求 CSRF。答疑问题、FAQ、检索材料等主要查询都按 `class_id` 限定；答疑详情对跨班和不存在的问题统一返回 404。
- **页面使用：** 用户访问 `/login` 登录；成功后从 `/qa`、`/materials`、`/tutor` 等页面进入功能。种子账号面向本地演示，README 明确指出默认凭据公开，不适合外部部署。
- **主要代码：** `campusclaw/views/auth_views.py`、`api_auth_views.py`、`request_context.py`、`sessions.py`、`security.py`、`views/qa_views.py`、`db.py`；页面模板位于 `campusclaw/templates/`。
- **存储与流程：** `users` 关联 `classes`；`auth_sessions` 保存会话摘要及撤销/过期时间。请求上下文从已验证会话或令牌解析可信用户身份，业务查询再带入班级 ID。
- **限制/缺口：** 答疑 API 的“登录本班成员”不等于资源作者权限。当前 AI 请求及详情中的最新 AI 结果没有作者过滤；转人工也未限制为问题作者或教师。班级范围检查已存在，但完整角色/资源权限尚未达到需求。

### 2.2 班级答疑广场：提问、回复、采纳、关闭

- **已实现功能：** `/qa` 列表支持状态、排序和分页；详情页支持学生/教师回复、教师采纳、关闭和重新打开。人工回复会将 `OPEN` 推到 `ANSWERED`，关闭问题会阻止后续回复。页面也提供取消采纳操作。
- **页面使用：** 登录后进入 `/qa` 浏览问题，打开详情发回复；教师在详情页选择回复采纳或关闭问题。
- **主要代码：** `campusclaw/views/qa_views.py`、`qa_db.py`、`templates/qa_list.html`、`templates/qa_detail.html`。
- **存储与流程：** `qa_questions` 保存班级、作者、状态、采纳回复及时间标记；`qa_replies` 保存人工回复。`add_reply`、`accept_reply`、`close_question` 使用 SQLite 事务，状态和回复的主要写操作原子完成。
- **限制/缺口：** 问题表没有版本字段，写 API 不进行乐观并发检查，也没有通用幂等键。问题正文上限为 5000、回复上限为 2000，分页默认 10/最大 50，与需求规定的 10000 和 20/100 不符。关闭没有原因字段；API 还提供需求明确不提供的重开和取消采纳。采纳可发生在非 `ANSWERED` 状态并可替换旧答案。

### 2.3 AI 辅助答疑及知识库检索

- **已实现功能：** 问题详情页可发起 AI 辅助，响应以 SSE 返回状态、引用、增量文本和完成/错误事件。答疑检索复用既有班级知识库，优先尝试混合检索，向量端异常时回退 SQLite FTS5 关键词检索。无模型配置时使用确定性本地回答。AI 结果单独存储，不进入人工回复表，因此不会推进答疑状态或计入人工回复统计。
- **页面使用：** 在 `/qa/questions/<id>` 详情页点击 AI 辅助，页面显示 AI 提示和材料引用。通用知识检索可从 `/knowledge` 使用；解题助手从 `/tutor` 使用。
- **主要代码：** `views/qa_views.py`、`retrieval.py`、`retrieval_db.py`、`tutor.py`、`qa_db.py`、`templates/qa_detail.html`、`templates/knowledge.html`、`templates/tutor.html`。
- **存储与流程：** `knowledge_chunks` 与 FTS5 保存可检索切片；`material_index.active_generation` 指向当前索引代次。查询按班级、有效材料及活动代次过滤。`qa_ai_answers` 保存回答、引用 JSON、请求者及检索模式。
- **限制/缺口：** 代码生成的公开引用来自本次检索命中，包含材料和切片定位信息，但没有在引用输出阶段按 FAQ 当前发布状态复核。AI 请求接口只检查本班与非关闭状态，没有核对当前用户为问题作者或教师；详情 API 将最新 AI 回答返回给任何同班成员。流式模型错误以 HTTP 200 的 SSE `error` 事件结束，未实现需求的 8 秒预算及超时 504/断连 503 契约。空检索仍进入本地/模型回答流程，不保证回答为空。

### 2.4 教师管理与 FAQ 知识沉淀

- **已实现功能：** 教师可从已采纳问题生成 FAQ 草稿，页面有“确认发布到班级 FAQ”按钮；可编辑、撤销和重新发布。已发布 FAQ 被渲染为本班 Markdown 汇总材料，写入材料存储并交给已有索引队列。
- **页面使用：** 教师在已采纳问题详情生成草稿并确认发布；在 `/qa/faq` 查看/管理 FAQ；FAQ 汇总材料随后可通过材料和知识库能力检索。
- **主要代码：** `views/qa_views.py`、`qa_db.py`、`qa_faq_material.py`、`retrieval_db.py`、`index_worker.py`、`templates/qa_detail.html`、`templates/qa_faq.html`。
- **存储与流程：** `qa_faqs` 记录来源问题/回复、内容和发布状态；每班用 `qa_faq_materials` 指向汇总材料。FAQ 变化重建 Markdown，更新材料正文并排入索引任务；索引 worker 构建新代次后切换活动代次。
- **限制/缺口：** FAQ 表没有版本、独立索引状态或删除任务状态。FAQ 重建捕获异常并只记录日志，API 仍返回成功；旧索引代次在新索引成功切换前仍可能被检索，检索查询也不直接复核 FAQ 当前状态。撤销后可编辑/重新发布，和规约“不恢复”冲突。没有 FAQ 级索引失败提示或明确重试流程。

### 2.5 教师统计面板

- **已实现功能：** 教师页面显示本班问题总数、待处理、已解决、关闭未解决、转人工待办及回复较多的问题；还显示每日新增问题趋势。
- **页面使用：** 教师打开 `/qa/stats` 查看汇总信息。
- **主要代码：** `views/qa_views.py`、`qa_db.py`、`templates/qa_stats.html`。
- **存储与流程：** 统计通过 SQLite 对 `qa_questions` 和 `qa_replies` 聚合，问题按当前状态与 `accepted_reply_id` 归类；AI 回答单独成表，当前热门回复统计因此只计人工 `qa_replies`。
- **限制/缺口：** `/api/qa/stats` 不接受日期窗口或返回 `as_of`；计数是全历史。热门列表按全历史回复数排序且默认前 5，不是需求的近 7 天前 10。每日趋势是最近有记录的本地日期，不等同于指定窗口统计。

### 2.6 其他功能：材料、通用知识助手与 MCP

- **材料管理：** 教师上传、重命名、删除 `.txt`/`.md` 材料，学生查看/下载本班材料。主要代码 `views/material_views.py`、`materials.py`、`storage.py`、`templates/materials.html`。文件保存于上传目录，元数据在 SQLite；材料删除涉及文件清理任务。
- **通用检索及解题助手：** `/knowledge` 提供关键词、向量和混合检索；`/tutor` 提供会话式 SSE 回答、引导/直接回答模式、提示词与技能管理。代码包括 `views/retrieval_views.py`、`conversation_views.py`、`prompt_views.py`、`skill_views.py`、`tutor.py`、`tutor_db.py`。
- **MCP：** 教师可从 `/mcp` 注册服务、连接并发现工具；技能可绑定白名单工具，调用有审计。服务端客户端和数据层位于 `mcp_client.py`、`mcp_db.py`、`mcp_skill.py`，独立服务位于 `mcp-server/`。
- **限制：** 本次审查未对这些功能运行端到端测试；实现基线/README 的功能描述不是运行验收证据。Qdrant、外部模型和 MCP 服务依赖额外配置及服务可用性。

## 5. 关键技术实现说明

### Flask 架构

`campusclaw/__init__.py` 创建 Flask 应用并注册多个蓝图。页面路由、API、领域/数据处理按模块分布在 `views/`、`qa_db.py`、`materials.py`、`retrieval.py`、`tutor_db.py` 等文件中。该结构是模块化单体，不是独立微服务；MCP 工具端为单独服务。答疑模块部分逻辑集中在较大的 `qa_views.py`，路由直接组合校验、数据访问、SSE 与检索流程，后续修改宜保持边界清晰。

### SQLite 表和关系

- 核心表位于 `db.py`：`classes`、`users`、`materials`、`auth_sessions` 等；用户属于班级，材料属于班级。
- 检索表位于 `retrieval_db.py`：`material_index`、`knowledge_chunks`、FTS5 虚表及 `index_jobs`，按材料生成代次保存切片和活动索引指针。
- 答疑表由 `qa_db.py` 建立：`qa_questions`、`qa_replies`、`qa_ai_answers`、`qa_faqs`、`qa_faq_materials`。问题关联作者和班级；回复与问题关联；AI 回答独立保存；FAQ 关联来源问题/回复；每班 FAQ 汇总材料映射到普通材料。
- 数据访问使用 SQLite 连接、外键及 `BEGIN IMMEDIATE` 事务，`busy_timeout` 为 5 秒。这样可保证当前事务范围内的写入原子性，但不提供业务版本比较或幂等语义。

### 认证、授权及跨班隔离

认证从服务端会话或 Bearer 凭据导出用户身份，答疑 API 不接受客户端声明身份字段。答疑教师接口先检查角色，Cookie 写请求要求 CSRF。查询显式加入班级 ID，跨班与缺失问题通常映射同一 404。需要修复的是同班对象级角色检查：AI、转交等当前允许普通同班成员针对他人问题操作/读取。

### 状态流转及并发

当前人工回复：问题未关闭时新增回复，OPEN/ANSWERED 进入 ANSWERED，ACCEPTED 保持。采纳操作将选中回复标记为 accepted 并写 `accepted_reply_id`；可替换既有答案，也可能在 OPEN 或 CLOSED 上执行。关闭仅设置 CLOSED 与时间；重开将 CLOSED 重新打开。问题没有 `version`，所以旧页面提交不会以版本冲突拒绝；`BEGIN IMMEDIATE` 只串行化写事务，不能表达业务层“同版本仅一个成功”的规则。

### FAQ 与索引一致性

FAQ 事实记录和索引是两个存储层：FAQ 操作更新 SQLite，再重写汇总 Markdown 并 enqueue 索引工作；worker 生成新代次完成后切换 `active_generation`。检索 SQL 只取当前活动代次且 ready 的材料切片。因此更新/撤销后，在新代次切换前，旧活动代次仍可能可检索。`qa_faq_material.rebuild` 捕获异常后返回空值，但上层没有检查返回值，FAQ API 仍返回成功。FAQ 状态没有传入检索查询作为二次有效性判断。

### AI 回答与引用

答疑 AI 复用 `retrieval.search` 或 `keyword_search`，最大检索 4 条。引用由命中对象构造，包含材料 ID、标题、切片序号、偏移、摘录及材料链接；不通过解析模型文本臆造引用。其可信前提是当前检索命中有效，而 FAQ 撤销/索引延迟未做二次复核。模型失败发生在 SSE 开始后，HTTP 状态已是 200，只能看到 `error` 事件；无模型时本地回答会输出固定模板。

### 错误及并发安全

答疑层对参数、未登录、教师权限、关闭状态等部分情况有明确状态码；SQLite/文件/索引依赖的错误映射并不统一。写问答和 FAQ 表的函数有事务，但文件系统更新和数据库提交不构成同一事务；异步索引最终状态也未在 FAQ 接口呈现。没有版本号、通用幂等键或用于防止旧索引任务复活的 FAQ 版本令牌。

## 6. 已确认问题与待验证风险

### 已确认的业务差距

1. **权限：** 同班非作者可对其他学生的问题请求 AI；详情 API 可返回最新 AI 回答。转人工没有作者/教师检查。
2. **状态规则：** 采纳可用于 OPEN/CLOSED，也能换采纳答案；存在取消采纳和重开接口，均与当前规约冲突。关闭操作缺原因输入/持久化。
3. **并发与重复提交：** 问题/FAQ 缺版本字段；发布问题、回复、FAQ 写入无统一幂等键。
4. **参数契约：** 正文/回复上限和分页默认值/上限低于规约；分页超限被截断，不一定返回 400。
5. **AI失败与无依据：** 空命中仍可能产出本地回答；模型流失败不能返回 504/503 HTTP 状态；未落实 8 秒目标。
6. **FAQ 撤销：** 撤销后允许重新发布；旧活动索引代次在新索引切换前仍可能检索；FAQ 重建失败对客户端不可见。
7. **统计：** 缺时间窗口与 `as_of`；热门列表是全历史前 5，不是 7 天前 10。

### 尚待测试确认

- 端到端验证 Cookie/Bearer 权限、CSRF、跨班问题/回复/FAQ/AI 资源返回 404 的完整矩阵。
- SQLite 锁竞争、事务提交失败和多 worker 场景；`BEGIN IMMEDIATE` 的忙等待不等同于需求定义的版本冲突。
- FAQ 索引失败、重试、旧任务延迟到达、撤销后检索结果和向量删除行为。
- 真实模型服务慢响应、断连、SSE 客户端取消以及引用输出的失效处理。
- MCP 白名单、令牌、恶意输出清洗和审计行为的自动化覆盖。
- `health` 的数据库表探针当前代码存在；结构化 JSON 日志/request ID 等平台规范能力应按实现基线另行验证，本次未测试。
