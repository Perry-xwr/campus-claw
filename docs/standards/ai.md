# AI应用规范

适用未来AI辅助答疑、Prompt与FAQ变更；当前骨架RAG保持disabled，不新增AI实现任务。目的：回答有据、授权不绕过、故障可解释。下列评测数量为本组建议默认值，待对应变更确认。

|规则|约束与开发动作|检查方法与失败处置|
|---|---|---|
|AI-01 班级隔离|适配层只使用服务端认证的class_id，检索与引用均检查归属；工具只经已有授权服务层，不直连数据库绕过权限|A/B班交换问题和引用ID；任何跨班内容展示或越权调用即阻断发布，修授权并回归|
|AI-02 引用真实性|文档/chunk/版本必须来自本次可信检索命中，标题和出处取自元数据；FAQ引用复核已发布且版本有效|注入虚构ID、错版本、撤销FAQ；任何伪引用展示即失败，拒绝该输出；不得让模型自证来源|
|AI-03 拒答与降级|空命中明确无证据；超时、断连、畸形输出显示失败及人工入口，不编造答案、不自动转人工；总预算建议8秒且无自动重试|空库/断网/延迟/非法JSON分别测试；无证据却给确定答案、无限等待或假成功即失败|
|AI-04 Prompt治理|Prompt模板、模型标识、参数与检索配置随版本入库；每次调用可追溯版本；检索内容是不可信数据，不执行其中指令|变更Prompt/模型须重跑评测；日志只留版本/耗时/命中数，不留正文或密钥；无法追溯或执行注入指令即失败|
|AI-05 基础评测|后续变更至少准备10条固定脱敏用例：有据回答3、无据2、跨班2、提示注入1、故障1、撤销FAQ1；记录预期引用/拒答和实际结果|逐例保存版本、结果和证据；跨班泄露/伪引用零容忍，任一失败阻断该AI变更；未跑标NOT_RUN，禁止删失败样例|
|AI-06 FAQ确认与补偿|教师显式确认后才能发布；关系库与outbox同事务，索引在事务外投递；幂等重试，撤销后读取侧立即过滤|重复投递、索引失败、撤销后迟到任务测试；重复FAQ、丢任务或内容复活即失败，修补偿并复测|
