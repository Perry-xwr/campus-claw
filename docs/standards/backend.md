# 后端开发规范

适用：骨架后端及未来API。具体探针/错误契约以本change design为准。目的：让错误、依赖和写入可预测、可测试。

|规则|开发动作与具体约束|检查方法|失败判定与处置|
|---|---|---|---|
|BE-01 分层|handler做协议解析；application编排；domain/ports不依赖SQL/HTTP框架；adapter做数据库/远程调用；cmd装配|`go list -deps ./...`结合import审查，检查SQL位置|反向导入、handler内SQL即失败，迁回正确层|
|BE-02 响应|统一code/message/data/request_id；HTTP与业务码一致；错误不包装200；ready503保留诊断data为唯一当前例外|按spec检查200/400/401/404/405/500/503的header和body|字段缺失、码不一致即失败，修封装和契约测试|
|BE-03 参数|边界校验类型、长度、枚举、未知/重复参数；health/ready无query；diagnostics仅一个dependency=mysql或rag|非法/遗漏/重复/未知参数表驱动测试|忽略非法筛选或退化全量即失败，补白名单；未来分页20默认/100上限，排序追加id|
|BE-04 配置|监听前解析必需项，不使用缺失默认值掩盖错误；依赖暂时断连以ready503反映|逐项移除配置并观察退出/端口；停止MySQL|缺配置仍监听即失败；连接故障被标up即失败|
|BE-05 事务|未来多行业务写入与outbox同事务；事务内不做RAG/HTTP调用；SQL参数绑定|代码审查事务边界、故障回滚测试|外部网络夹在事务内或半写入即失败，拆outbox补偿；L7不建业务表|
|BE-06 并发/幂等|未来写接口声明幂等键、作用域、保留期与载荷冲突；修改已有资源必须比较版本|相同键重复/不同载荷、两会话同版本测试|重复副作用或静默覆盖即失败，增加唯一约束与原子比较|

未登记业务API在本课必须404，不用空实现返回成功。业务状态、RAG与FAQ仅在后续变更定义后实现。
