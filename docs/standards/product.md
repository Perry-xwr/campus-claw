# 产品设计规范

适用：L7状态页及未来业务页面。数值为本组建议默认值，待确认。目的：使用户可判断当前状态，并能从失败恢复。

|规则|开发动作与具体约束|检查方法|失败判定与处置|
|---|---|---|---|
|PRD-01 范围/路由|L7仅根状态页和404页；显示项目名称、版本、就绪状态。不添加假业务入口。未来路由在相应change登记|逐路由访问，对照spec及tasks|未登记业务页面/假数据即失败，删除越界实现或另提变更|
|PRD-02 四态|加载显示“加载中”；正常显示状态；无数据才显示“暂无数据”；失败显示“加载失败，请重试”。MySQL不可用显示“服务未就绪”，不能当成空数据|延迟响应、正常响应、空fixture、断依赖逐项检查|白屏/无限加载/故障显示为空即失败，补全状态与重试|
|PRD-03 校验/连点|未来表单失焦提示、提交前全量校验；后端同样校验。标题/正文限制以功能说明为准；提交中禁用按钮，保留失败输入，重试复用幂等键|空白、上下限及超限、双击、断网后重试|超限被接受或重复写入即失败，修前后端及测试；L7无业务表单则不创建|
|PRD-04 状态流转|使用功能说明的四状态及权限；CLOSED不再回复；409提示“内容已变化，请刷新后重试”，不自动覆盖|状态表逐边验证、两个会话并发|UI允许后端禁止的操作或状态随意赋值即失败，按规约修正|
|PRD-05 视觉与可达性|间距4/8/16/24px；正文16px、行高1.5；按钮可键盘聚焦且有可见焦点；状态不能只靠颜色；宽360/768/1280px无横向溢出|键盘走查、三宽度截图、检查文本标签|焦点不可见、按钮无标签或主内容被截断即失败，修复后复查|

检查结果记录到验收记录；未来业务条款当前标NOT_RUN，不为使规范“生效”而越界开发。
